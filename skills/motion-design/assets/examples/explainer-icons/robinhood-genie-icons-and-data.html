The problem

Same question, different tables, different counts

Asked "How many Gold subscribers," different tables gave different answers.

Safety

The agent can read. It cannot write.

It runs as the actual user, limited to read-only statements, on its own query cluster.

Verification

A mandatory critic loop cost time and changed nothing

1.5x slower and about 34% more tokens, with no statistically significant accuracy gain.

Provenance

Every answer ships with the SQL behind it

The agent plans, gathers context, writes and verifies SQL, then responds with the query shown.

Take the docs away and the agent picks the right table half the time

Databricks: building high-performing Genie spaces

Four explainer icons. Headlines are taken from the article's best practices.

Step 1: data foundation

Define revenue once, in a metric view

Shared metrics are defined in one place so Genie inherits a single approved definition.

Step 2: benchmarks

Write the test questions first, then rerun them after every change

Expect early failures that reveal missing context; rerun to track progress and catch regressions.

Step 3: vocabulary

Teach it that "Australia" means AUS

Synonyms and value dictionaries let Genie match the words people use to the values in the data.

Step 3: joins

State the join's cardinality, or the rows multiply

Declaring one-to-one, one-to-many or many-to-many prevents row explosion and double-counting.
